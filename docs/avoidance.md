# 장애물 회피와 주행 제어

12일차 C 작성. 코드는 `src/obstacle_avoider/obstacle_avoider/avoider.py`, `safety.py`.

## 입력과 출력

| 방향 | 토픽 | 내용 |
|---|---|---|
| 입력 | `/obstacle/front_distance` (`Float32`) | 정면 ±15도 최소 거리. `+inf` 장애물 없음, `-inf` 너무 가까움, `NaN` 측정 실패 |
| 입력 | `/odom` (`Odometry`) | 정지(stuck) 감지용 위치 |
| 출력 | `/cmd_vel` (`TwistStamped`) | 10 Hz 타이머로 발행 |

## 상태 흐름

```text
           d < 1.0            d < 0.5            0.3초 경과
FORWARD ───────────> SLOW ───────────> STOP ───────────> ROTATE
   ▲  ▲   d > 1.5     │                 │ d > 1.5           │ d > 1.5
   │  └───────────────┘                 └──> FORWARD        ▼
   │                  1.0초 경과                          RECOVER ── d < 0.5 ──> STOP
   └──────────────────────────────────────────────────────────┘

d ≤ 0 (-inf) 또는 전진 중 1초간 3 cm 미만 이동(stuck)
   ──> BACK (후진 0.8초) ──> TURN (90도) ──> FORWARD
   180초 안에 3회째이면 ──> GAVE_UP (정지 유지)

d가 NaN이거나 0.5초간 미수신 ──> 상태 유지, 정지 명령, 상태 타이머 정지
```

| 상태 | 명령 (선속도, 각속도) | 빠져나가는 조건 |
|---|---|---|
| `FORWARD` | (0.2, 0) | `d < 0.5` → `STOP`, `d < 1.0` → `SLOW` |
| `SLOW` | (0.1, 0) | `d < 0.5` → `STOP`, `d > 1.5` → `FORWARD` |
| `STOP` | (0, 0) | `d > 1.5` → `FORWARD`, 0.3초 → `ROTATE` |
| `ROTATE` | (0, 0.5) | `d > 1.5` → `RECOVER` |
| `RECOVER` | (0.2, 0) | `d < 0.5` → `STOP`, 1.0초 → `FORWARD` |
| `BACK` | (-0.1, 0) | 0.8초 → `TURN` |
| `TURN` | (0, -0.5) | 90도 회전 시간(약 3.1초) → `FORWARD` |
| `GAVE_UP` | (0, 0) | 없음 (재시작 필요) |

## 설계 이유

| 결정 | 이유 |
|---|---|
| 감속(1.0 m)과 정지(0.5 m) 두 단계 | 0.2 m/s로 달리다 바로 서면 관성으로 밀린다. 먼저 0.1 m/s로 줄인다 |
| 복귀 거리 1.5 m > 정지 거리 0.5 m (히스테리시스) | 같은 기준을 쓰면 경계에서 정지·전진이 반복 전환된다 |
| `STOP`에서 0.3초 대기 후 회전 | 정지 직후 바로 회전하면 미끄러지며 측면이 닿을 수 있다 |
| `RECOVER`를 1초 둔다 | 회전 직후 `FORWARD`로 가면 같은 장애물의 가장자리에서 다시 감속한다 |
| `NaN`·미수신은 정지 | 앞을 못 보는 상태에서 움직이지 않는다. 상태 타이머도 멈춰 복구 동작 시간을 건너뛰지 않는다 |
| `-inf`는 후진 | 센서 최소 거리(0.12 m)보다 가까우면 제자리 회전도 위험하다 |
| stuck 감지 | 정면 밖 장애물에 걸려 바퀴만 도는 경우를 `/odom` 이동량으로 잡는다 |
| 재시도 3회 제한 후 `GAVE_UP` | 끼인 위치에서 무한 반복하지 않고 사람이 개입하게 한다 |

모든 값은 ROS 파라미터(`stop_dist`, `slow_dist`, `recover_dist`, `linear_x`, `angular_z`, `stop_time`, `recover_time`, `scan_timeout`, `back_*`, `turn_*`, `stuck_*`)로 바꿀 수 있다.

## 회피 성공률 시험 (11일차)

`bash scripts/run_avoid_trials.sh [위치별 반복=3]`

- 5일차 판정 대상 10곳 × 3회 = 30회를 무작위 순서로 실행한다 (`SEED`로 순서 재현).
- 회차마다 `avoid_trial` 노드가 70초 감시하고 `avoid_trials.csv`에 1행, `avoid_trace_<회차>.csv`에 시점별 거리·명령을 남긴다. 상태 전환은 `launch_<회차>.log`의 `avoider` 로그에 있다.
- 판정 (`scan_check.trial_verdict`, 5일차와 같은 기준):

| 판정 | 조건 |
|---|---|
| 제외 | 회차 전체 이동 5 cm 미만 (스폰 직후 끼임) |
| 실패 | 전체 방향 최소 거리 ≤ 0.15 m (접촉 의심) |
| 제외 | 정면 거리가 0.5 m 밑으로 내려간 적 없음 (정지 동작 미발동) |
| 통과 | 그 외 |

**왜 30회인가.** 성공률은 표본이 적으면 불확실성이 크다. 5일차 9/10회는 목표 80%를 넘지만 95% 신뢰구간(Clopper-Pearson)은 56~100%라 "80% 이상"이라고 말할 수 없다. 30회에서 실패 1회 이하(29/30)이면 하한이 83%로 목표를 넘는다. `summarize_trials.py`가 성공률, 신뢰구간, 목표 충족 여부를 함께 출력한다.

## 접촉 의심 원인 분석 방법 (5일차 `(9.0, -15.0)`)

1. `run_avoid_trials.sh`로 같은 위치를 반복 실행한다.
2. `avoid_trials.csv`의 `min_all_sector`, `min_all_t_sec`로 최소 거리가 나온 방향과 시각을 본다.
3. `avoid_trace_x9.0_y-15.0_*.csv`에서 그 시각 전후의 `cmd_lin`, `cmd_ang`를 보면 어떤 동작(회전 / 후진 / 전진) 중이었는지 알 수 있다.
4. 회전 중 측면이면 `angular_z`를 줄이거나 회전 전 짧게 후진하는 방안을, 전진 중 측면이면 감지 구간(`front_deg`) 확대를 검토한다.

원인 확정은 시뮬레이션 실행 결과가 필요하다 (미확인).

## 알려진 한계

- 정면 ±15도 밖 장애물은 피하지 않는다. stuck 감지는 이미 걸린 뒤에 동작한다.
- 회전 방향이 고정(`ROTATE`는 왼쪽, `TURN`은 오른쪽)이라 좌우 여유 공간을 보지 않는다.
- `GAVE_UP` 뒤에는 노드를 다시 시작해야 한다.
- 목표 지점 없이 장애물만 피하며 돌아다닌다. 경로 계획은 범위 밖이다.
